# Security Policy

## Supported versions

The project is pre-release. Security fixes are made on the latest main branch only.

## Reporting a vulnerability

Do not open a public issue for vulnerabilities, credential exposure, sandbox escapes, approval bypasses, or unsafe application paths.

Report it privately through GitHub: open the repository's **Security** tab and choose **Report a vulnerability** (GitHub private vulnerability reporting). Include:

- affected revision and environment;
- minimal reproduction;
- expected and observed safety boundary;
- impact and any known workaround.

Do not publish exploit details before a fix is available. The maintainer should acknowledge a valid report within seven days and coordinate disclosure after a fix is available.
